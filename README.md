## История и аналитика заказов поставщику

- Вход через кнопку заказов в самом модуле, без ручной загрузки JSON.
- Список строится из компактного `orders-index.json` в Cloudflare R2 и не скачивает исходные Excel.
- Один исходный отчёт образует общий блок, внутри которого заказы «Камни» и «Жемчуг» считаются и завершаются независимо.
- **«Продолжить заказ»** или **«Открыть заказ»** автоматически восстанавливает исходный Excel и нужный облачный черновик.
- Завершённые заказы показываются вместе с активными и при необходимости скрываются переключателем.
- Кнопка **«Информация по заказу»** раскрывает фактическую аналитику в штуках, а не в количестве SKU.
- Для камней сначала показываются общий итог и номенклатурные группы, затем «Топовые камни» и «Цветные камни» с детализацией по семьям и конкретным камням.
- Для жемчуга показываются общий итог, номенклатурные группы и детализация по видам жемчуга.
- Limited Order показывается отдельно и не входит в количественную аналитику основного заказа.
- После завершения камни и жемчуг получают статус «Заказ отправлен». Статусы «Заказ в работе» и «Shipping» сохраняют жёлтую подсветку, а «Получен» переводит только выбранный подраздел в зелёный статус.
- В карточке хранится дата каждого этапа: отправка, передача заказа в работу, shipping и получение.
- Заказы, внесённые вручную, можно редактировать без удаления; после добавления форма очищается автоматически.
- Ручные ожидаемые поставки можно добавить по названию, дате, количеству изделий и комментарию, а затем вести по той же статусной цепочке.
- Удаление выполняется только после подтверждения и удаляет весь workspace: Excel, оба черновика, историю, резервные JSON, метаданные, запись индекса, локальный SQLite, локальные файлы и session-state.
- После удаления приложение повторно проверяет префикс workspace в R2; при остаточных объектах заказ остаётся в индексе и показывается ошибка.

## Режим «Заказ поставщику»

### Рекомендации 1.10.1

- В разделе заказа поставщику отчёт всегда считается как утверждённый четырёхмесячный период; подпись дат используется только информационно.
- Горизонт закупки — два месяца. Потребность округляется вверх.
- Перед началом заказа выбирается режим **«Базовые рекомендации»** или **«Сезонные рекомендации»**. Сезонный режим один раз уменьшает расчёт на единицу, после чего применяется общий минимум поставщика.
- Финальная автоматическая партия: `0 → 0`, `1 → 0`, `2 → 3`, `3+ → без изменения`.
- Рабочий остаток исключает точки `20 / 20NDC / Princess Hang` и `63 / 63NDC / 63.*`.
- Последняя единица в обычном магазине не считается перемещаемой. Со склада `Stock TT` можно перемещать весь остаток.
- TT — приоритетная торговая точка. Для серёг, колец и подвесок действуют отдельные матрицы пополнения.
- Браслеты исключены из этого заказа: они закупаются у другого поставщика.

### Категории изделий

**Серьги**

- `TT = 0`: при продажах создаётся заказ; активные модели обычно получают 5, более слабые — минимум 3.
- `TT = 1`: от двух продаж — минимум 3; активные модели без обычного перемещаемого запаса — 5.
- `TT = 2`: слабые продажи считаются обычным способом; заметные и активные модели могут получить минимум 3.
- `TT ≥ 3`: отдельная TT-логика отключается, остаётся обычная потребность.
- Если в комплекте несколько серёг, выводится короткая отметка **«Не единственные серьги в комплекте»**.

**Кольца**

- Целевая комплектность: топовые комплекты `5 серёг : 4 кольца`, средние и слабые `5 : 3`.
- Если колец нет в рабочей сети и продажи хорошие, рекомендация покрывает все рабочие магазины и 2 единицы в TT.
- Для слабых моделей без колец достаточно минимальной партии 3 с приоритетом 2 единиц в TT.

**Подвески**

- `TT = 0` и хотя бы одна продажа — минимум 3.
- Наличие последней единицы в магазине или единицы на Stock TT не отменяет заказ поставщику.
- Без собственных продаж, но в топовом комплекте — минимум 3.
- `TT = 1`: от двух продаж — минимум 3.
- `TT = 2`: минимум 3 при заметных продажах и недостатке перемещаемого запаса.
- `TT ≥ 3`: обычный расчёт.

**Крестики**

- Хорошо продающиеся крестики добиваются до рабочего запаса 5.
- Если была хотя бы одна продажа и остаток больше нуля, рабочий запас добивается до 3.
- Для позиции с `0 продаж / 0 рабочего остатка` выполняется проверка возможного дубля среди крестиков того же камня.
- Сначала учитываются продажи и остатки. Если активности нет у обеих моделей, выбирается более новый год после `KP`, `SKP` или `P`.
- Совпадение хвоста артикула — сильный признак; при изменившемся номере используется визуальное сравнение фотографий.

### Замена замка серёг

Рядом с `Limited Order` для серёг доступна кнопка **«Заказать другой замок»**. Текущий замок определяется по букве после двух цифр года в SKU и показывается отдельно. Пользователь выбирает другой вариант из справочника с русской расшифровкой. Выбор не меняет SKU и количество. В основном Excel появляется колонка `Change Lock To`; для неизменённых моделей она остаётся пустой.

### Рабочий процесс

1. Загрузите исходный Excel.
2. Выберите **Камни** или **Жемчуг** — это независимые черновики.
3. Выберите базовый или сезонный режим рекомендаций.
4. Проверьте продажи, общий остаток, TT, 63, ТВП, перемещения и рекомендацию.
5. Подтвердите рекомендацию, измените количество вручную, добавьте `Limited Order` или выберите другой замок для серёг.
6. Распределите размеры колец 15–24.
7. Скачайте основной Excel и при необходимости отдельный Limited Order.

### Надёжность черновика

Версия 1.10.1 использует приватное S3-совместимое объектное хранилище как постоянный источник истины. Исходный Excel хранится в облаке. Изменения количества, замка и размеров мгновенно сохраняются локально, а в облако отправляются пакетно, при ручном сохранении, переходах между этапами, подготовке Excel и завершении заказа.

После обновления страницы, нового деплоя или открытия приложения на другом компьютере заказ появляется в меню **«Незавершённые заказы»**. Приложение скачивает исходный Excel из облака в новый временный runtime и восстанавливает черновик.

Локальный SQLite остаётся только быстрым резервным кэшем. Предыдущие заказы больше не удаляются при загрузке нового отчёта. Для независимой страховки доступен полный ZIP: исходный Excel + выбранные позиции + manifest.

Перед работой обязательно настройте хранилище по инструкции [`ORDER_STORAGE_SETUP.md`](ORDER_STORAGE_SETUP.md). При `required = true` приложение не позволит начать новый заказ без успешной облачной копии.

## Основная структура Sonu

Модуль Sonu полностью перестроен в компактный управленческий отчет из пяти последовательных групп:

1. Серьги.
2. Кольца.
3. Подвески.
4. Браслеты не полный круг.
5. Браслеты полный круг.

В каждом блоке выводятся:

- таблица по камням;
- количество проданных уникальных SKU;
- проданные изделия;
- общий Total продаж в USD;
- количество SKU на остатке;
- общий сетевой остаток в штуках;
- диаграмма по штукам;
- диаграмма по Total продаж;
- рекомендации к заказу.

Рекомендации не используют горизонты 30/45/90 дней. Решение строится по двум управленческим сигналам:

- продажи высокие, а остаток и выбор SKU низкие;
- SKU на остатке мало, но штук много — запас сконцентрирован в оставшихся непродающихся моделях.

Из Sonu удалены разбивка по магазинам и фильтр проб: весь ассортимент поставщика рассматривается как серебряный. Остаток берется один раз на SKU по всей сети, а продажи суммируются по магазинам.
