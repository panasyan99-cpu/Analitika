# Analitika Web 2.6.0 — Reliability & Recovery

Дата релиза: 31.07.2026

## Защита сохранения заказов поставщику

- Интерфейс больше не сообщает «сохранено», когда запись не прошла ни в локальную SQLite-базу, ни в Cloudflare R2.
- Результаты локального и облачного сохранения проверяются отдельно.
- Закрытие или смена активного заказа блокируется, если оба способа сохранения завершились ошибкой.
- Для каждой попытки сохраняется безопасное диагностическое событие без паролей и токенов.

## Устойчивое облачное хранение

- Проверка R2 получила TTL 45 секунд вместо бессрочного отрицательного кэша.
- Временные сетевые ошибки проверяются повторно с задержкой.
- Кнопки обновления выполняют принудительную повторную проверку.
- Статус облака больше не должен оставаться красным до следующего деплоя после кратковременного сбоя.

## Решения Sonu

- Ручная классификация спорных моделей хранится в R2.
- Локальный JSON остаётся резервной копией, но не является единственным источником.
- При загрузке объединяются данные сессии, локальной копии и облака.
- Решения сохраняются между деплоями и перезапусками приложения.

## Склад и Baserow

- Открытие склада больше не изменяет структуру Baserow автоматически.
- Раздел «Диагностика» показывает найденные таблицы, поля, права чтения/записи, доступность загрузки файлов и состояние R2.
- Исправление структуры выполняется только после показа плана и явного подтверждения.
- Проверяются реальные write-endpoints Baserow, а не только наличие токена.
- Исправлено несоответствие названий полей серебряной приёмки: `Расчётное количество по весу` и `Погрешность веса, г`.
- Импорт поставки стал возобновляемым: после частичной ошибки повторный запуск продолжает тот же импорт и не создаёт дубликаты карточек, строк поставки или операций.
- В поставке сохраняются Import ID, статус, прогресс и последняя ошибка импорта.

## Журнал действий

- Добавлен безопасный аудит бизнес-операций: создание/редактирование карточек, импорт поставки, приёмка, передача в бухгалтерию, корректировка, удаление и сверка Baserow.
- Журнал хранится локально и, при доступном R2, дублируется в облако.
- Поля с названиями `password`, `secret`, `token`, `authorization` и похожими автоматически скрываются.
- Последние записи можно скачать из складской диагностики.

## Большие файлы

- Лимит приложения остаётся 150 МБ; рабочие файлы около 95 МБ не блокируются.
- Складской файл копируется во временную папку потоково, без создания дополнительной полной копии в памяти.
- После сохранения и разбора отчёта заказа поставщику лишняя копия исходных байтов освобождается.

## Проверки интерфейса

- Для 105 действий Streamlit сформирован статический реестр.
- Все действия имеют явные уникальные ключи; пропущенных и дублирующихся ключей нет.
- Реестр проверяется в GitHub Actions при каждом push и pull request.
- Добавлен безопасный Playwright smoke-тест развёрнутого сайта: вход, открытие всех верхних разделов, складские вкладки и обновление диагностики без проведения рабочих операций.

## Совместимость

- Общий пароль сайта и существующая модель доступа сохранены.
- Ограничение по ролям не добавлялось.
- Streamlit Secrets не переносятся в архив и не перезаписываются при деплое.
